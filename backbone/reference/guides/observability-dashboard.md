## What Is It?

The Observability Dashboard is your **daily command center** for managing all projects generated by the Agentic Backbone. Instead of checking each project individually, you get a unified view of health, version status, and recent activity across your entire portfolio.

**Access:** Open the Dev Portal home page (`/`)

---

## Dashboard Sections

### 1. Overview Stats Bar

Six cards at the top show the big picture:

| Stat | Meaning |
|------|---------|
| **Projects** | Total number of registered projects |
| **Healthy** | Projects with running services and up-to-date backbone |
| **Warning** | Projects that are outdated or have minor issues |
| **Error** | Projects with stopped services or critical failures |
| **Outdated** | Projects running an old backbone version |
| **No Runtime** | Projects without Docker Compose observability stack |

**Usage:** Click the Refresh button to get the latest data.

---

### 2. Health Grid

A card grid showing every project with color-coded status:

- 🟢 **Healthy** — Services running, backbone up to date
- 🟡 **Warning** — Services running but backbone is outdated
- 🔴 **Error** — Services stopped or in error state
- ⚪ **No Runtime** — No observability stack configured

**Each card shows:**
- Project name (click to open project detail)
- Framework badge (Quarkus, Spring Boot, etc.)
- Current version (with → latest if outdated)
- Number of running services
- Last commit message
- Visual status bar

**Usage:** Click any project card to view its full detail page.

---

### 3. Version Drift

Lists all projects that need a backbone update:

- Project name
- Current version → Latest version
- "Update All" link to bulk update page

**Usage:** Click "Update All →" to go to the projects page and update everything at once.

When all projects are up to date, you see a ✅ confirmation.

---

### 4. Activity Feed

Recent commits across ALL projects, sorted by time:

- Project name
- Commit message
- Author
- Relative timestamp (2h ago, 1d ago)

**Usage:** Scroll to see more history. Shows the last 10 commits by default.

---

### 5. Quick Actions

Shortcut links to common Dev Portal pages:
- 📁 My Projects
- 📚 Browse Skills
- 📋 View ADRs
- ⚡ Generator

## How Status Is Calculated

The dashboard determines project status by combining two signals:

### Runtime Health
Reads Docker Compose status to check if services are running.

### Version Drift
Compares each project's `backbone/VERSION` against the generator's latest template version.

### Status Matrix

| Runtime | Version | Status |
|---------|---------|--------|
| Running | Up to date | 🟢 Healthy |
| Running | Outdated | 🟡 Warning |
| Stopped | Any | 🔴 Error |
| None configured | Any | ⚪ No Runtime |

## API Endpoints

The dashboard is backed by four API routes:

### GET /api/dashboard/overview
Returns aggregate statistics:
```json
{
  "total": 8,
  "healthy": 5,
  "warning": 2,
  "error": 0,
  "outdated": 2,
  "noRuntime": 1
}
```

### GET /api/dashboard/health
Returns health data for all projects:
```json
{
  "projects": [
    {
      "name": "api-gateway",
      "status": "healthy",
      "version": "2026.04.26",
      "latestVersion": "2026.04.26",
      "framework": "quarkus",
      "hasRuntime": true,
      "servicesRunning": 4
    }
  ]
}
```

### GET /api/dashboard/drift
Returns outdated projects:
```json
{
  "outdated": [
    {
      "name": "user-service",
      "currentVersion": "2026.04.20",
      "latestVersion": "2026.04.26"
    }
  ]
}
```

### GET /api/dashboard/activity?limit=10
Returns recent commits across projects:
```json
{
  "commits": [
    {
      "project": "api-gateway",
      "message": "feat: add rate limiting",
      "author": "Peter",
      "date": "2026-04-26T10:30:00Z",
      "hash": "a1b2c3d"
    }
  ]
}
```

## Architecture

### Files

```
dev-portal/src/
├── lib/dashboard.ts              # Core logic: overview, health, drift, activity
├── pages/
│   ├── index.astro               # Dashboard page (enhanced home page)
│   └── api/dashboard/
│       ├── overview.ts           # Aggregate stats API
│       ├── health.ts             # Project health API
│       ├── drift.ts              # Version drift API
│       └── activity.ts           # Recent commits API
```

### Key Functions

**`getDashboardOverview()`**
- Iterates all projects
- Checks runtime status and version for each
- Returns aggregate counts

**`getProjectsHealth()`**
- For each project: reads version, detects framework, checks runtime
- Runs `git log` to get last commit
- Returns array with status, version, services, etc.

**`getVersionDrift()`**
- Compares each project's `backbone/VERSION` with `templates/backbone/VERSION`
- Returns list of outdated projects

**`getRecentActivity()`**
- Runs `git log` for each project
- Sorts all commits by timestamp
- Returns top N entries

## Troubleshooting

### Dashboard shows "No projects registered yet"
You haven't added any projects. Go to **My Projects** and click "Register Project" to add your first service.

### Version drift shows incorrect versions
Make sure each project has a `backbone/VERSION` file. If a project shows "none" or "unknown", it was registered before the VERSION tracking was added.

### Activity feed is empty
Projects must be git repositories with at least one commit. Non-git projects won't show activity.

### Health status is "No Runtime" for all projects
Projects need the observability stack. Run `./scripts/init-backbone.sh --runtime` in each project directory, or regenerate the project with the `--runtime` flag.

### Framework shows "Unknown"
The framework detection looks for `pom.xml` (Maven/Quarkus), `build.gradle` (Gradle/Spring), or `package.json` (Node.js). If your project uses a different build file, detection may fail.
